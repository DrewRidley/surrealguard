TypeScript

Four packages: a typed client, a framework-agnostic reactive core, and Next.js and SvelteKit adapters with live queries and SSR handled.

@surrealguard/client @surrealguard/query @surrealguard/next @surrealguard/svelte

@surrealguard/client

A typed wrapper over any SurrealDB-like connection. Pass a string literal to query and its result and parameters resolve from the generated registry; a dynamic string falls back to unknown and still runs.

import { SurrealGuardClient, fromSurreal } from "@surrealguard/client";
import "./surql.gen"; // the module augmentation from `surrealguard generate`

const db = new SurrealGuardClient(fromSurreal(surreal));

const users = await db.query("SELECT name FROM user WHERE team = $team", { team: "red" });
//    ^ Array<{ name: string }> — result & params inferred from the query text

await db.query("SELECT name FROM user WHERE team = $team");
//    ✗ Expected 2 arguments, but got 1.  (params are required when the query reads them)

fromSurreal adapts a SurrealDB JS SDK Surreal instance to the client's Connection interface (kept structural, so the package doesn't depend on the SDK). Since the SDK returns one result per statement, the adapter returns the first statement's result.

The typing trick

Params are required exactly when the query reads them, forbidden otherwise. This is one conditional generic — ParamsArg<P> — proven against tsc. There is deliberately no permissive string overload: a second overload would defeat the inference, so query stays a single generic.

type ParamsArg<P> = P extends Record<string, never> ? [] : [params: P];

query<Q extends string>(query: Q, ...args: ArgsOf<Q>): Promise<ResultOf<Q>>;

Use db.raw to reach the underlying connection for live queries and lower-level access. The package also exports RecordId<T>, GeoJSON, Connection, LiveNotification, ResultOf, ArgsOf, SurqlRegistry, and ParamsArg.

surrealguard generate

surrealguard generate scans your host files for embedded SurrealQL, analyzes each query against the schema, and emits a module augmentation of @surrealguard/client — one registry entry per analyzed query, keyed by its exact text.

declare module "@surrealguard/client" {
  interface SurqlRegistry {
    "SELECT * FROM user": {
      result: Array<{ id: RecordId<"user">; name: string }>;
      params: Record<string, never>;
    };
  }
}

Import the generated file once and every matching db.query("…") across the app is typed. The base SurqlRegistry is empty; the generated file only ever adds entries. See the CLI for --out and discovery.

@surrealguard/query

A framework-agnostic reactive core. A QueryClient owns a cache of results keyed by (sql, params); observe reference-counts subscriptions so N subscribers to the same query share one live subscription and one reconciled array.

import { QueryClient } from "@surrealguard/query";

const qc = new QueryClient(db);           // wraps a SurrealGuardClient
const handle = qc.observe("LIVE SELECT * FROM user", { initialData });
const stop = handle.subscribe((state) => render(state.data));
  • Dedup. Identical (sql, params) calls share one cache entry via a stable queryKey; the first subscriber starts it, the last to leave tears it down.
  • Live reconcile by id. A LIVE SELECT seeds with current rows, then applies change notifications to the array keyed by record id — CREATE and UPDATE upsert, DELETE removes. A plain query resolves once.
  • SSR. dehydrate() snapshots successful cached results for transport; hydrate(state) seeds the client cache so the first render has no gap, then (for live queries) upgrades in place.
  • fetch(sql, params) runs a one-shot query outside the reactive layer (e.g. in an SSR load).

State is { data: Row[], status: "loading" | "success" | "error", error? }. The framework packages are thin bindings over the Observable returned here.

@surrealguard/next

A React useLiveQuery hook. Server components fetch typed data with client.query(...) and pass it as initialData; the client component seeds from it (no hydration gap), subscribes on mount, reconciles live notifications, and releases the reference-counted subscription on unmount.

import { useLiveQuery } from "@surrealguard/next";

function Users({ qc, initial }) {
  const { data, status } = useLiveQuery(qc, "LIVE SELECT * FROM user", {
    initialData: initial,
  });
  return data.map((u) => <li key={u.id}>{u.name}</li>);
}

Built on useSyncExternalStore; it re-observes only when the query or its params change, and the server snapshot is the seeded state.

@surrealguard/svelte

A liveQuery store for SvelteKit. A +page.server.ts load fetches typed data and returns it; the page seeds the store with initial, which subscribes on mount and unsubscribes on destroy — Svelte stores tear down automatically when the last subscriber leaves.

<script>
  import { liveQuery } from "@surrealguard/svelte";
  export let data;
  const users = liveQuery(qc, "LIVE SELECT * FROM user", { initial: data.users });
</script>

{#each $users.data as user (user.id)}
  <li>{user.name}</li>   // reconciled live: CREATE / UPDATE / DELETE by id
{/each}

Returns a Readable<QueryState<Row>>; the underlying subscription is reference-counted and released when the store loses its last subscriber.
