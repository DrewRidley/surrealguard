SurrealGuard

Static checks for SurrealDB apps: catch schema/query drift before it becomes a runtime surprise.

You keep SurrealQL. The surrounding tooling finally understands it.

The split brain

Your SurrealDB schema knows the truth. Your app code cannot see it.

The seam is the query boundary: typed host code hands SurrealQL text to the database, and the compiler loses sight of fields, params, and graph edges.

Application

type User = {
  name: string
  age: number
}

const q = `SELECT name, age FROM user`
query boundary

Database

DEFINE TABLE user SCHEMAFULL;
DEFINE FIELD name
  ON user TYPE string;
DEFINE FIELD age
  ON user TYPE int;
