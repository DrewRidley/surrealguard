## 2. Shared-infrastructure groups

**PREREQ-A — Flow-narrowing capability (B0).** Statement/branch env narrowing on two guard shapes (NONE-equality, `type::table($p)='lit'`). No diagnostic of its own. **Unlocks B1, B2, B3 and fixes a live false positive** (spurious 5002 on workshop `fn::drive::record::can_read`). Files: `expression/infer.rs`, `flow/block.rs`, `flow/if_else.rs`. Reuses A1's divergence predicate.

**PREREQ-B — Permission-predicate lowering.** Add `permissions: Vec<Spanned<Expr>>` (structured FOR-clauses) to `ast::DefineTable`/`DefineField`; stop discarding at `lower/statement.rs:940-946 / :1052-1055`; walk each predicate in a child env (row scope + open `$auth`/`$session`). **Unlocks F0, F2, F3, F4 with essentially no per-check code.**

**PREREQ-C — `kind_for_path` schema threading.** Thread `&SchemaIndex` into `kind_for_path`; at a record-link/graph-landing boundary, when the target is a single schemafull table, recurse instead of collapsing to `Kind::Any`. **Unlocks E1, E3, and the field-on-record half of B3.** File: `data/select.rs`.

**SHARED-LEAF — `check_membership_kind` + `comparable`.** New helper in `check.rs` called from the `Op::Other` branch. **Serves C2 and D2.**

**STANDALONE LEAVES** (no shared infra): E2, H1, H2, H3, C1, C3, C4, D1, D3, D4, A1, A2, A3, G1, G2, G3.

## 5. What unlocks the most

1. **PREREQ-A (flow-narrowing, #10)** is the highest-leverage single item: it is the *only* item that **fixes a live false positive** (the workshop `can_read` spurious 5002) **and** unblocks three new checks (B1/B2/B3). Do it right after A1, whose divergence predicate it reuses.
2. **PREREQ-B (permission lowering, #11)** turns one AST change into **four** diagnostics (F0/F2/F3/F4) at near-zero marginal code — the best effort-to-coverage ratio in the backlog. The workshop's permission-heavy schema means these are high-real-impact "silent total deny" bugs.
3. **PREREQ-C (`kind_for_path` schema threading, #9)** is the shared spine of the entire cross-record field-existence story: **E1, E3, and B3** all collapse to "rebase the row table, reuse 1002" once it exists. Build it via E1 (the simplest consumer), then E3 and B3 are incremental.
4. **`check_membership_kind` (#8)** is small but serves both C2 and D2 — build it in the comparison position first, reuse in the ASSERT position.

**Suggested execution order:** E2 → H3 → H2 → C1 → D1 → A1 → (A1 gives you the divergence predicate) → B0 → H1 → C2 → E1(PREREQ-C) → PREREQ-B → F0/F2 → then the below-the-line items in the two now-unblocked clusters.
